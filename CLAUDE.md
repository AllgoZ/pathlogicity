## What this is

Marketing site for **Path Logicity**, India's largest Multimodal Logistics Park (about 400 acres, Dobbaspet, Bengaluru), built by PATH Group. A homepage-first site: one long scrolling homepage (about 16 sections plus the footer) and six inner pages that reuse the same section components (`/path-group`, `/logicity-advantage`, `/sustainability`, `/site-tour`, `/news`, `/blogs`). The only server code is `POST /api/enquiry`. The design idea is a thin gold **route line** that threads the page (the hero's own gold route line, then the Scale section, then the left-margin "spine" down to the enquiry block).

## Commands

```bash
npm run dev          # http://localhost:3000 (Turbopack)
npm run build        # production build, everything statically generated
npm run start        # serve the build (.claude/launch.json "prod" uses port 3100)
npm run typecheck    # tsc --noEmit  (no test runner, no linter)
```

- Add `?annotations=on` to any URL to reveal review-only placeholder slots (hidden from visitors by default).
- `ENQUIRY_WEBHOOK_URL` (see `.env.example`) is required in production. Unset in dev, the API logs the payload and succeeds. Unset in production, it answers `503` and the form shows a call/email fallback.
- Playwright (`playwright-core`) is used for ad-hoc QA; Lighthouse runs via `npx lighthouse http://localhost:3100/ --preset=desktop`.

## Stack

Next.js 16.4 (App Router) · React 19.3 (Server Components by default, `"use client"` islands) · TypeScript strict (`@/*` maps to the repo root) · Tailwind v4 (CSS-first `@theme` tokens in `app/globals.css`, no `tailwind.config`) · GSAP + ScrollTrigger · Lenis (mouse and trackpad only) · Manrope (headlines) + Inter (body) via `next/font/google`. Runtime deps are only `gsap`, `lenis`, `next`, `react`, `react-dom`. Do not add an animation library.

## Layout (essentials)

- `app/page.tsx`: homepage, a server component that composes the sections. `app/layout.tsx`: shared chrome (Nav, RouteSpine, JourneyRail, MobileActionBar, EnquireBlock, Footer, providers).
- `components/<area>/`: section components (hero, stats, master-plan, project-status, path-group, gallery, advantage, connectivity-map, sustainability, site-tour, news, blogs, contact, footer, navigation, providers, ui).
- `content/home.ts`: **the only place facts live.** `lib/content/index.ts` (getters) and `lib/content/types.ts` (models) are the CMS swap point.
- `lib/motion/`: `gsap.ts` (`MQ` media-query presets), `hooks.ts` (`useMotion`, lazy shared IntersectionObserver), `route.ts`, `useLinks.ts`.
- `public/client/`: client assets (see `MANIFEST.md`). `public/client/amenities/` and `public/construction/` are labelled stock imagery with `CREDITS.md`.

## Rules that matter

1. **Fact safety.** Only client-supplied facts appear as claims. Never invent numbers, dates, coordinates, news, blog posts, ESG metrics or testimonials. An unknown fact is `null` or an empty list in `content/home.ts` and renders a `ContentSlot` or a designed empty state. Stock images are always labelled "Illustrative" and credited (the repair photo is CC BY 2.0 and must keep its credit).
2. **Components never import `content/` directly.** They get data as props from `lib/content` getters.
3. **Accent words** in headlines are wrapped in `*asterisks*` in content strings (`lib/accent.tsx` turns them into `<em>`, which is a colour, not a second typeface).
4. **Design system:** light theme. The footer is the only dark surface. The hero and the nav dropdowns sit on deep ink over the photograph / panel, with white text and gold accents. Gold (`--color-yellow-400`, currently `#ffd60a`) is the action accent and is never used for small text on white. Indigo is for headings, numerals and links. Labels are sentence case with no tracked all-caps eyebrows. No section numbers in kickers (names only).
5. **Motion must degrade.** Scenes run inside `useMotion` and `gsap.matchMedia()` (`MQ.motion` / `desktop` / `mobile`) so nothing animates under reduced motion. Content must be fully visible without JS. Animate transforms and opacity only (CLS must stay 0). Only two desktop scenes hold the page, briefly: the Scale list (about 1.4 viewports, M26) and the Renders gallery (about 2 viewports, M5); the hero is **not** pinned. Phones and reduced motion never hold the page. Do not add more pins without being asked. Scroll-state hooks re-render only when a threshold is crossed, never per frame.
6. **Hover-only effects must also play by themselves** (client round 8): add `data-flow` to items inside a `ui/Flow` group and put `group-data-[lit=true]:` next to every `group-hover:` class.
7. **Accessibility is a standing requirement** (Lighthouse a11y is 100 everywhere): one `h1` per page, real control lists behind every interactive diagram, visible focus rings, ARIA tabs for News.
8. **Scope discipline for client rounds:** change only what the feedback names, write the plan to `docs/PLAN-CLIENT-ROUND-N.md` (feedback, reading, plan, questions), and record it in the HANDOVER change log and the ARCHITECTURE header.

## Gotchas

- The route spine (`RouteSpine`) measures real section tops, so reordering sections is safe, but it starts at `#explore` and ends at `#enquire`.
- On the homepage the order is: Hero, Scale, Master plan, Project status (+ Space availability), Renders, PATH Group verticals (`PathLegacy`), Hub opener, At a glance, Amenities, Connectivity, Gati Shakti, Sustainability, Business value, Inside Logicity, PATH Group (About), News, Enquire, Footer. Inner pages wrap content in `<div data-inner>`.
- The §03/§06.1/§09 maps share the official plan (`/client/image-1731136566206.webp`, 2774×1583). §07 and §07.1 share the location map (`/client/345.webp`) and its routes in `connectivity-map/mapGeometry.ts`.
- The hero photograph (`hero-v4.webp`, a large warehouse at sunset) is labelled "Illustrative image". Do not caption it as the site or call it Warehouse 17 unless the client says so. The hero must keep `id="top"`, `data-stage="discover"` and the `[data-hero-end]` sentinel (nav threshold, spine and rail read them).
- Pinned scenes insert pin-spacers, and ScrollTrigger refreshes triggers in **creation order**, so a pin created later (the Scale pin is created a few frames after mount) leaves earlier-created pins below it (Renders) measured too early: the section pins ~1.4 screens before it arrives and leaves a blank stretch after. Give a pin higher on the page a higher `refreshPriority` than the pins below it (Scale = 1, Renders = default 0) and re-measure once after it is created. Also, `RouteSpine` measures section tops at load and ~1.2 s later, so create pins at mount, not lazily far below the fold as `useMotion` would.
- Screenshots taken with Playwright inject `caret-color` on inputs and trigger a harmless React hydration warning; it is the test tool, not the site.
- Unused leftovers (safe to delete): `PlanSvg.tsx`, `planGeometry.ts`, `MmlpNetwork.tsx`, `SurveyGrid.tsx`.
- Dev-only noise: the Next dev badge, and `reactStrictMode` double-running effects (all scenes use reverting contexts).
- Commit or push only when asked. Rounds 8 and 9 are on `main`; the working tree is otherwise the source of truth.
